## 3. 詰まったこと / 学んだこと

- Linux で `go build` すると次のエラーが出る。Ebitengine が GLFW 経由で X11 を使うため。

  ```
  fatal error: X11/extensions/Xrandr.h: No such file or directory
  ```

  解決:

  ```sh
  sudo apt-get install -y libx11-dev libxrandr-dev libxcursor-dev \
      libxinerama-dev libxi-dev libxxf86vm-dev libgl1-mesa-dev
  ```

  macOS / Windows では不要。CI（ubuntu-latest）にも同じ手順を入れた。

- 論理解像度を返す `Layout` の意味を理解した。`Layout` が固定値を返す限り、ゲーム側のコードは
  常に 320x240 の座標系だけを考えればよく、拡大縮小は Ebitengine が担当する。

## 5. 設計メモ

- `Draw` の中で `ticks` を増やしたくなったが、我慢して `Update` に置いた。
  Ebitengine は処理落ち時に `Draw` をスキップするため、`Draw` で状態を進めると
  重い環境でだけゲームが遅くなるバグになる。
- `main.go` にロジックを書かないと決めた。`main` は「組み立てて実行する」だけにしておくと、
  後でテスト用の別エントリポイント（例: ヘッドレスでバランス調整を回す）を足しやすい。

**CC0 = パブリックドメイン相当。** 商用・改変・再配布すべて自由、クレジット表記も不要。
public リポジトリへの同梱に問題がないことを確認してから取り込んだ。

### 分かったこと

- **このパックは自分で解析する必要がほとんど無かった。** `tile_list_v1.7`（座標一覧）と
  `frames/`（切り出し済みPNG）が最初から同梱されており、以前2つのパックで自力でやった
  グリッド解析・連結成分抽出が不要だった
- 公式READMEに「壁(16x32)はY+8px（一部-2px）のオフセットで16x16グリッドに乗せる」と
  明記されていた。これは前回、別パックを目視解析して立てた「壁は下端合わせで描く」という
  仮説と一致する。**推測が公式仕様と合っていたのは収穫**
- キャラクター・モンスターのフレームサイズは16x16ではなく、16x28（人型）や16x23（小型）など
  種類によって縦幅が違う。描画は「足元をタイル境界に合わせる」方式になる
- `_f`/`_m`（性別）× idle/run/hit という命名規則が統一されているキャラクター
  （dwarf, elf, knight, lizard, wizzard）が5種あり、プレイヤーキャラの題材として扱いやすい
