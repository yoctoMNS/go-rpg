## Day 21 — 当たり判定の土台

| 項目 | 内容 |
| --- | --- |
| 目安 | 45分 |
| 触るファイル | `internal/physics/collider.go` + テスト |
| 学ぶこと | AABB 判定 / 判定用矩形と描画用矩形を分ける |

### やること

1. `physics.Collider` を作る
   ```go
   // Collider は当たり判定用の矩形。
   // Offset は Actor の位置からのズレ。足元だけを判定に使うために必要。
   type Collider struct {
       Offset geom.Vec2
       Size   geom.Vec2
       Solid  bool
   }
   func (c Collider) BoundsAt(pos geom.Vec2) geom.Rect
   ```
2. **判定用の矩形は見た目より小さくする**
   - キャラチップが 32x32 でも、判定は足元の 16x8 程度にする
   - これをやらないと「頭が壁にめり込めない」不自然な操作感になる（2DRPGの定石）
3. `Collider` を `Actor` に持たせる
4. F1 デバッグ表示に **当たり判定矩形を赤枠で描く** 機能を足す

### 動作確認

```sh
make run
```

- [ ] F1 でプレイヤーと NPC の足元に赤い枠が出る
- [ ] 枠がキャラの足元に正しく位置している

## Day 22 — タイルとの当たり判定

| 項目 | 内容 |
| --- | --- |
| 目安 | 55分 |
| 触るファイル | `internal/physics/resolve.go` + テスト |
| 学ぶこと | 軸分離による移動解決 / すり抜けバグの原因 |

### やること

1. **X軸とY軸を別々に解決する**（これが最重要）
   ```go
   // 1. X だけ動かす → 衝突したら X を戻す
   // 2. Y だけ動かす → 衝突したら Y を戻す
   //
   // XとYを同時に動かして判定すると、壁に沿って滑れず、
   // 斜め移動が壁際で完全に止まってしまう。
   func ResolveMove(c Collider, pos, delta geom.Vec2, m *tilemap.Map) geom.Vec2
   ```
2. 移動先の矩形が重なるタイルだけを調べる（全タイルを走査しない）
   ```go
   minCol := int(bounds.X) / tileSize
   maxCol := int(bounds.X+bounds.W-1) / tileSize
   // ... 最大でも 2x2 = 4 タイルしか見ない
   ```
3. **テストを厚く書く**（当たり判定のバグは目視で見つけにくい）
   - 壁に真っ直ぐ突っ込む / 壁に沿って斜め移動する / 角に入り込む / 1px の隙間

### 動作確認

```sh
make run
```

- [ ] 壁に向かって歩いても抜けない
- [ ] 壁に沿って斜めに歩くと、壁に沿って**滑る**（止まらない）
- [ ] 高速（ダッシュ）でも壁を抜けない

### ポイント

- 「壁をすり抜ける」バグの原因はほぼ **移動量が判定サイズを超えている**（トンネリング）。
  1フレームの移動量をタイルサイズ未満に保つか、移動を分割する
- ここのテストは、この先ずっと自分を守ってくれる資産になる

## Day 24 — カメラ追従とスムージング

| 項目 | 内容 |
| --- | --- |
| 目安 | 45分 |
| 触るファイル | `internal/camera/follow.go` |
| 学ぶこと | 補間（lerp）/ 境界クランプ |

### やること

1. カメラがプレイヤーを画面中央に捉えるようにする
2. **マップ端でカメラを止める**（マップ外の黒い部分を見せない）
   ```go
   c.Pos.X = clamp(target.X-float64(c.ViewW)/2, 0, mapPixelW-float64(c.ViewW))
   ```
3. スムージングを入れる（線形補間）
   ```go
   // 追従係数 0.1 = 1フレームで目標との差の10%だけ近づく。
   // 1.0 だと即座に追従して硬く、0.05 だと柔らかいが酔いやすい。
   const followLerp = 0.1
   c.Pos = c.Pos.Add(target.Sub(c.Pos).Scale(followLerp))
   ```
4. **カメラ座標を描画時に整数に丸める**（丸めないとタイルの継ぎ目に線が出る）

### 動作確認

```sh
make run
```

- [ ] キャラを動かすとカメラが滑らかに追従する
- [ ] マップの端まで行ってもマップ外の黒が見えない
- [ ] タイルの継ぎ目にちらつく線が出ない

### ポイント

- `followLerp` を 0.05 / 0.2 / 1.0 に変えて**体感の違いを確かめる**。
  こういう「数値ひとつで手触りが変わる」感覚がゲーム開発の面白さの核心
