## Day 31 — 日本語フォントを表示する

| 項目 | 内容 |
| --- | --- |
| 目安 | 50分 |
| 触るファイル | `internal/ui/font.go` `assets/fonts/` |
| 学ぶこと | `text/v2` / フォント埋め込み / ドット絵と可読性の両立 |

### やること

1. 日本語フォントを用意して `assets/fonts/` に置く
   - 推奨: [PixelMplus](https://itouhiro.hatenablog.com/entry/20130602/font)（M+系ドットフォント）や
     [美咲フォント](https://littlelimit.net/misaki.htm)（8x8 の極小フォント）
   - **ライセンスを `assets/CREDITS.md` に記録する**
2. `ebiten/v2/text/v2` の `GoTextFaceSource` でフォントを読み込む
3. `ui.Font` にまとめる（本文用・見出し用でサイズ違いを2つ持つ）
4. **フォントサイズは論理解像度に合わせる**。320x240 に 16px フォントは大きすぎるので、
   8〜12px 前後を選ぶ

### 動作確認

```sh
make run
```

- [ ] 画面に日本語（ひらがな・漢字）が表示される
- [ ] 文字が滲まずくっきり出る（サイズと拡大倍率が合っている）

## Day 33 — メッセージの1文字ずつ表示

| 項目 | 内容 |
| --- | --- |
| 目安 | 50分 |
| 触るファイル | `internal/ui/messagebox.go` + テスト |
| 学ぶこと | ルーン単位の扱い / 折り返し計算 |

### やること

1. `ui.MessageBox` を作る
   - `SetText(s string)` / `Update()` / `Draw()` / `IsFinished() bool`
2. **1文字ずつ表示する**
   - `[]rune` に変換して数える（**`len(string)` はバイト数。日本語で必ず壊れる**）
   - 表示速度は「Nフレームに1文字」で管理
3. `ActionConfirm` で「全文即時表示」→ もう一度押すと「次のページ」
4. **自動折り返し**を実装する（1行の最大文字数で折る）
5. 折り返しロジックにテストを書く（英数字混在、長い単語、改行文字入り）

### 動作確認

```sh
make run
```

- [ ] メッセージが1文字ずつ表示される
- [ ] Z キーで全文即時表示される
- [ ] 長い文章が自動で折り返され、ウィンドウからはみ出さない

### ポイント

- 「1文字ずつ」は**必ず `Update` で進める**。`Draw` で進めると処理落ち時に速度が変わる
- 日本語は `rune` 単位。ここを間違えると文字化けする

## Day 34 — 会話を Command 列として表現する

| 項目 | 内容 |
| --- | --- |
| 目安 | 55分 |
| 触るファイル | `internal/dialogue/command.go` `internal/dialogue/player.go` |
| 学ぶパターン | **Command** |

### やること

1. `dialogue.Command` を定義する
   ```go
   // Command は会話イベントの1命令。
   // Execute は1フレーム分進め、その命令が完了したら true を返す。
   type Command interface {
       Execute(ctx *Context) (done bool)
   }
   ```
2. 実装を作る
   - `ShowText{Text string}` — メッセージ表示
   - `Wait{Frames int}` — 待機
   - `SetFlag{Key string; Value bool}` — フラグ操作
   - `Choice{Prompt string; Options []string; Branches [][]Command}` — 選択肢
3. `dialogue.Runner` が Command 列を先頭から順に実行する
4. **`Choice` が分岐先の Command 列を持つ**（＝Composite）。これで会話ツリーが表現できる
5. `Runner` のテストを書く（表示系をフェイクにすれば、分岐の正しさだけを検証できる）

### 動作確認

```sh
make run
```

- [ ] コードで組み立てた会話（テキスト2つ + 選択肢）が最後まで再生される
- [ ] 選択肢によって表示される文章が変わる

### ポイント

- **これが Command パターンの威力**。「やること」がデータになったので、
  会話を JSON で書けるようになり（W10）、シナリオ追加でコードを触らなくなる
- 戦闘の行動（W9）もまったく同じ形で表現できる

## Day 35 — NPC に話しかける

| 項目 | 内容 |
| --- | --- |
| 目安 | 45分 |
| 触るファイル | `internal/scene/field/interact.go` |
| 学ぶこと | インタラクション判定 / シーンとUIの協調 |

### やること

1. プレイヤーの**向いている方向の1タイル先**に矩形を作り、NPC と重なるか調べる
2. 重なっていて `ActionConfirm` が押されたら、その NPC の会話を開始する
3. **会話中はプレイヤーを動かせないようにする**
   - `FieldScene` に `talking bool` を持たせる……ではなく、
     **`FieldScene` 自体を状態で分ける**（`fieldStateWalk` / `fieldStateTalk`）
   - W3 で学んだ State パターンをここで再利用する
4. NPC が向きを変えてプレイヤーの方を向く演出を足す

### 動作確認

```sh
make run
```

- [ ] NPC の正面に立って Z を押すと会話が始まる
- [ ] 背後や離れた位置では話しかけられない
- [ ] 会話中はキャラが動かない
- [ ] 会話が終わると再び動けるようになる

### 今週の振り返り（ログに書く）

- `Command` インターフェースのメソッドは1つで足りたか
- 会話を JSON で書くとしたら、どんなスキーマになりそうか（W10 の準備）
