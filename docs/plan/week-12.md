## Day 58 — 手触りの調整（ゲームフィール）

| 項目 | 内容 |
| --- | --- |
| 目安 | 50分 |

### やること

分類 B を、**数値の調整だけ**で直せるものから片付ける。

| 調整対象 | 目安 |
| --- | --- |
| 移動速度 | 1画面（20タイル）を横断するのに 3〜4 秒 |
| カメラ追従係数 | 0.1 前後。硬すぎず酔わない値を探す |
| メッセージ送り速度 | 2〜3 フレーム/文字 |
| エンカウント率 | 20〜40 歩に1回 |
| 戦闘の演出待ち | 各アクション 20〜30 フレーム |

1. **調整したい数値を1か所に集める**（`internal/config/tuning.go`）
   - 散らばっていると調整のたびに探し回ることになる
2. 1つ変えては `make run` で確かめる。**まとめて変えない**
3. 決めた値と「なぜその値か」をコメントに残す

### 動作確認

```sh
make run
```

- [ ] 15分遊んで、ストレスを感じる箇所が無い

### ポイント

- ゲームの面白さの大半は**数値の手触り**で決まる。設計と同じくらい重要な作業

## Day 59 — 最終リファクタリングと Component 化の検討

| 項目 | 内容 |
| --- | --- |
| 目安 | 55分 |
| 学ぶパターン | **Component 指向**（ECS への布石） |

### やること

1. 大きくなったファイル / 型を数える
   ```sh
   find internal -name '*.go' ! -name '*_test.go' | xargs wc -l | sort -rn | head -20
   ```
2. `Player` / `NPC` / `Enemy` に重複しているフィールドを洗い出す
3. **Component 化する（する価値があれば）**
   ```go
   type Transform struct{ Pos, Vel geom.Vec2 }
   type Sprite    struct{ Sheet *sprite.Sheet; Anim *sprite.Animator }
   type Collider  struct{ Box geom.Rect; Solid bool }
   type Health    struct{ HP, MaxHP int }

   type Entity struct {
       Transform Transform
       Sprite    *Sprite   // nil = 描画しない
       Collider  *Collider // nil = 当たり判定なし
       Health    *Health   // nil = 破壊不能
   }
   ```
4. **本格的な ECS には進まない。** エンティティが数千体になって実際に重くなるまでは、
   複雑さの負債にしかならない。その判断理由をログに書く
5. `go vet ./...` に加えて、余裕があれば `staticcheck` を導入する

### 動作確認

```sh
make check && make run
```

- [ ] 通しプレイが Day 58 とまったく同じ手触りで動く
